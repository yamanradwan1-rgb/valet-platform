## Cross-slice production blockers

These gates apply to the future production implementation; prototype completion does not satisfy them.

- **ALT-13:** Seen must repeat the protected source authorization and MFA assurance used by the force-ended Shift reader for Location Managers.
- **Seven-day source-of-truth boundary:** Preview eligibility, `seenEligible`, and Seen insert/retry must use one accepted PostgreSQL-time equality comparator.

- **Production UI-02:** provide a canonical typed DTO and lookup handle, exact source selection, source-scope-specific read, and fresh by-ID destination reauthorization. ALT-15 requires a separate CA-only Organization-scoped read/Seen/fan-out path independent of selected Location.
- **No-write retirement:** implement ALT-12 time-only expiry and seven-day retirement for all five OCCURRENCE families (ALT-05/07/09/13/15), without relying on a new source write. Unknown source timestamps remain null; never invent a time.
- **Cross-device invalidation:** Seen and timing-preference mutations must invalidate all active devices for the same User+Organization and never another user's state.
- **Writer cutover:** deploy and attest the fixed Phase1 Dispatch and Phase2/3 Stage writer builds, drain old writers/transactions, then capture separate DB-server UTC-millisecond cutovers for each phase. Never reuse or infer timestamps.

## Per-slice procedural rules

1. Before code, check current repo `AGENTS.md`, `docs/17_AGENT_CODE_STRUCTURE_RULES.md`, current accepted DECs, intended source file size, latest `origin/main` and relevant test baseline. Record entity/ValetSession/Task transitions (observational changes only unless a separately approved source-domain change), tenant/Location, SQL constraints and policy inheritance.
2. Prepare a small branch and isolated writer worktree per slice. Never edit root `main`; preserve user changes and coordinate high-contention contracts, migration and app-module files. No two workers write the same file concurrently.
3. For each proposed API/DTO change write contract and source-authorization tests first; for new source-writer events verify commit vs rollback and race identities; for UI use browser acceptance and source-aware mocked fixtures then real bearer integration.
4. Produce exact final-SHA lint/typecheck/build/architecture/test and Security CI evidence. A successful unit test does not certify production behavior. A source-only independent review does not certify real PG or deployment.
5. Do not merge one slice until its agreed exit gate is independently reviewed and approved in the normal repo workflow. A merge does not close a cutover, migration, acceptance or activation task.

- **H01** cannot create a legitimate post-lock timestamp until every relevant old writer and transaction is quiescent. Two cutovers have different source families and never share a fixture/deploy timestamp.
