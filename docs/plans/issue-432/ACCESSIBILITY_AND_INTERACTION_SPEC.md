## Component semantics and visual hierarchy

1. The bell is the real Dashboard `<button type="button">` in its existing topbar slot, with persistent localized accessible name, scoped count/status, `aria-expanded={open}` and stable `aria-controls` referencing the panel when present. Do not leave `aria-haspopup="dialog"` after removing the dialog; do not claim `aria-haspopup="menu"` for a list containing local demo actions and independent Seen buttons. Bell glyph is decorative (`aria-hidden`); visible badge communicates `0`, `1`, multi-digit, `20+` and `—` (unconfirmed), while the accessible name translates those values meaningfully. The prototype-only UI-01 treatment is **borderless**, with a 44×44 CSS px target, 18px glyph, existing count treatment and visible focus ring in the same topbar slot. The outlined production bell remains unchanged when the override is absent. Do not add a duplicate bell.
2. The non-modal popover is anchored immediately below the bell, at the **trailing edge** of the control (visually right in LTR, left in RTL), without a page-dimming backdrop, focus trap, body-scroll lock or `aria-modal`. Model it as a labelled `<section role="region" aria-labelledby="…">` or a naturally labelled section (not a `role="menu"` or `role="dialog"`). Use a local heading, optional Close button, and an ordinary semantic `<ol>`/`<li>` list. Ordinary Dashboard content remains visible and keyboard-accessible.
3. Each row presents priority (text plus distinctive visual indicator, not color alone), localized meaningful title, **only verified safe** short description, authorized Location/source context if supplied, and `<time dateTime>` only for an authoritative recorded timestamp. If time is `null`, use a localized “time unavailable”/“current condition” indication without inventing elapsed time. Display mixed Arabic/English names/IDs in `<bdi>` or `dir="auto"` spans; long Arabic must wrap and must not overflow. Keep category codes out of the routine primary title/description; an optional diagnostic label may expose them separately. The active locale must also set the document's effective `lang` (`ar`/`en`) and `dir` (`rtl`/`ltr`) for screen-reader pronunciation and native text flow, not only the inner popover's `dir`.
4. **Prototype local synthetic navigation implemented and E2E exercised.** The available ALT-08 fixture uses source ID `SIM-INC-1042` and target ID `SIM-TARGET-INCIDENT-1042`; a native anchor changes only `#SIM-TARGET-INCIDENT-1042` and opens an in-memory `No production record` preview containing both IDs. `unavailable`, `missing` and `unauthorized` remain distinct non-link states. Initial-hash restoration, reload/new tab and `hashchange`/`popstate` Back/Forward are covered by Worker2's final **8/8 headless and 8/8 headed/debug PASS**. Manual-open native-anchor Back keeps the panel open, while hash-opened Back closes and Forward reopens. Production pathname/query and API remain unchanged. The synthetic link does not prove production exact-source selection, source re-read or independent by-ID authorization; those remain P1 release requirements.
5. An `OCCURRENCE` may have a **separate** explicit “Mark Seen” button. An `ACTIVE` never has Seen. Clicking the bell, row, scrolling, viewing, closing, refreshing or following a link is never Seen, source acknowledgment or domain mutation. Production Seen removes attention only after a server-confirmed per-user receipt; show inline pending/failure feedback and prevent duplicate submission. The prototype's Seen state is a local simulation, not a server receipt or production Seen API. Do not imply Seen accepts or resolves the underlying incident, task, payment or shift.
6. Keep status text for **loading, no eligible alerts, temporarily unavailable, definitive access loss, and retry**. A failed/unknown read must display no authoritative `0`; `—` or an explicit unconfirmed indicator is appropriate. Distinguish “no alerts” from “not loaded” and “access denied”. Use restrained `role="status"/aria-live="polite"` announcements for user-initiated changes and debounced new-alert summaries; use `role="alert"` for an explicit action error where necessary, not each polling/invalidation cycle. Do not force focus or repeatedly announce the whole changing list.

## Interaction state model

The panel state and trusted data state are orthogonal. Panel = `CLOSED | OPEN`. Data = `UNAVAILABLE | LOADING | READY(items,count,hasMore) | SUSPENDED`. Scope/authority generation is part of the identity of every response; a prior scope's data must never be displayed after a scope change.

| Event | State transition and required result | Focus result |
| --- | --- | --- |
| Bell pointer/touch click while closed | `CLOSED → OPEN`; anchor under same bell; show current authorized data/status; no Seen | Remain on trigger; arm one forward-Tab entry. The first Tab is consumed once and focuses the first enabled panel button after geometry is ready; if geometry is pending, defer that one focus safely |
| Bell Enter/Space while closed | `CLOSED → OPEN`; `aria-expanded=true`; no scroll jump | Move to first actionable demo/Close control after mount, or panel heading with `tabIndex=-1` if empty/loading. If Tab arrives before geometry/positioning is ready, defer focus safely and enter the panel once; do not let the panel close or lose the key event. |
| Bell click while open | `OPEN → CLOSED`; no duplicate overlay | Bell remains focused; do not reopen on the same gesture |
| Escape while open, including when focus is on list control | `OPEN → CLOSED`, only handle Escape for this panel when it is the active applicable overlay | Restore to still-mounted bell and do not override a higher-level modal's Escape |
| Outside `pointerdown` (mouse, pen, touch) | Close once when target is outside both bell and panel (including when portal-mounted); never block target's normal click | Let clicked outside control receive native focus; do **not** refocus bell |
| Tab or Shift+Tab through bell/panel | After pointer-open, first Tab enters once. Shift+Tab from the first panel control returns to bell with the panel OPEN; the next forward Tab exits to the next shell control and closes. No focus wrap or trapped Tab. | Native `focusin` outside bell/panel closes without stealing focus. Final four-spec headless/headed runs each **8/8 PASS** for exercised keyboard/focus scenarios |
| Activate synthetic row anchor | ALT-08 opens fixture-only `#SIM-TARGET-INCIDENT-1042` with `SIM-INC-1042` source ID and `SIM-TARGET-INCIDENT-1042` target ID, preserving production pathname/query and no production writes. `No production record` stays visible. | Focus preview. Hash-opened Back closes the panel and Forward reopens; Back from a manually opened native anchor retains the panel. Worker2's final authenticated 8/8 headless and 8/8 headed/debug E2E cover these local history behaviors |
| Explicit Seen click on `OCCURRENCE` | Pending → local simulated success/removal or inline retryable error in the prototype; production requires server-confirmed removal and badge change | On success, focus the first still-present subsequent eligible Seen action in captured order; if none remains, focus the nearest still-present preceding eligible action; if neither exists, focus Close/panel heading. Use captured IDs, not the removed row's former numeric position. On failure, restore focus to the same row's retry action, or Close if unavailable |
| Authoritative data push/refetch while open | Update both rows and badge atomically; preserve stable keyed item, keyboard focus, scroll position when practical | If focused row is removed, move to adjacent actionable row or heading; never silently dump focus to body |
| Refresh/reconnection/transient error | Display loading/unconfirmed or a clearly labelled stale snapshot; never silently turn a failure into zero | Preserve current user focus/scroll; retry remains available |
| Logout, definitive denial, expired session, Organization/Location switch or revocation | Cancel/fence outstanding reads/actions, retire old preview, close panel; do not reveal old rows | Keep focus on the surviving action that caused the transition; otherwise use a safe shell focus target |
| Localized language/theme change while open | Retain state and row identity; re-render translation and placement within viewport | Keep focus on same semantic control where it persists |
| Browser route navigation / popover unmount | Close/clean listeners and subscriptions | Do not programmatically restore focus to a removed trigger |

**Implementation and verified E2E:** The source uses one-shot `pointerTabEntryArmed`, deferred geometry entry and a document `focusin` guard to maintain native Tab behavior. Final headless **8/8 PASS** and headed/debug **8/8 PASS** exercise immediate keyboard Enter→Tab with held/released RAF, Shift+Tab to bell with panel open, forward Tab exit/close, outside click/Escape, Seen recovery, fragment history and auth fixtures. This is local synthetic UI behavior; production links require separately approved exact source and by-ID authorization and would retain native modifier-key behavior.

## Anchoring, bidi, touch and responsive geometry

- The physical position follows bell's live bounding box and the **available visual viewport**, not a fixed center-screen coordinate. Anchor beneath the control with a small gap; place at the logical trailing edge based on effective `dir`, then shift inward to stay within both viewport edges. Recalculate after resize, scrolling, zoom, font load, dir change, and mobile orientation/visual viewport changes; avoid magic fixed `right` values that misplace Arabic.
- A portal or equivalent clipping-safe layer may be necessary: `shell.css:177-184` has `.shell-main { overflow: hidden }`. Confirm no ancestor clips the panel and that stacking remains above page content but below a genuinely active modal. No invisible backdrop intercepts clicks or blocks the nearby locale/theme buttons.
- Target width roughly 22–26rem on wide screens, capped with `min(…, calc(100dvw - safe margins))`; at 320/390 CSS px use a nearly full-width anchored panel with measured inset, not horizontal page scrolling. Height limited by available below-bell viewport space and safe-area insets; allow independent vertical scrolling of the list while keeping the heading/critical controls reachable. Test short landscape/mobile heights; if below-bell space is insufficient, fit above or within visual viewport without covering the bell itself.
- `min-inline-size: 0`, `overflow-wrap: anywhere` for untrusted long labels, logical padding/margins/insets, and `<bdi>` for mixed direction. Avoid truncating the only meaningful incident description; a clamped preview needs an accessible way to reach the full **authorized** source detail. No nested scroll traps, overlapping fixed footer, or hidden bottom action at 200% browser zoom.
- Touch interaction: hit targets ~44px in each dimension for bell, Seen, Close and refresh; when a category later proves an exact target and receives a native link, that link must also meet the 44px target. Preserve scroll on a finger swipe, do not trigger navigation from a swipe, avoid hover-only affordances and pointer hover as the only severity distinction. Responsive shell layout and topbar controls must remain unchanged outside this feature.
- Use existing semantic tokens for foreground, border, surface, focus and severity; no new raw hard-coded colors. Test Windows high contrast/forced-colors, dark/light readability, visible focus, and reduced-motion settings.
