### Decision-status separation

- **Accepted product/security contracts:** DEC-109 OD-01–06; DEC-110 OD-07A–D; DEC-111 OD-08A–G; applicable DEC-108 revocation semantics; Issue #414's 17-category scope with ALT-14 disabled. These bind category policy, source authority, recipient scope, timing/Seen semantics and exclusions. DEC-110 specifies a seven-day window but does **not** settle exact equality; current list and Seen-write predicates disagree there. These decisions do **not** prove the corresponding technical mechanism or release readiness.
- **Existing source-verified implementation:** scoped HTTP preview/detail/Seen readers and the foreground 60-second polling baseline; ALT-15 is included as a null-Location CA source candidate. ALT-17 has a subscription-page notice and a separately tested source-reader helper, but the helper is not wired into a production route.
- **Proposed, not Accepted by DEC-109/110/111:** SSE-over-`fetch`, PostgreSQL `LISTEN/NOTIFY`, transaction-coupled invalidation, per-replica listeners, 100–250 ms coalescing, finite stream leases, a 60-second degraded-mode reconciliation read, and authenticated long-poll fallback. - **Not evidenced:** a production Dashboard/API topology, a Management Alerts post-commit publisher/outbox, two or more running API replicas, cross-instance delivery, deployed streaming ingress, or a production latency/SLO result.

## Options and conditional recommendation

| Transport | Security/operational fit | Decision |
| --- | --- | --- |
| **Short-lived SSE over `fetch` with a bearer header**, transporting only invalidation hints; ordinary existing scoped GET supplies count/list. | Matches existing in-memory bearer transport and one-way event need. Requires verified Next/proxy streaming without buffering, bounded stream lifetime, disconnect and admission accounting. Native browser `EventSource` cannot add the existing Authorization header. | **Preferred candidate if T0 passes**; not a deploy decision |
| WebSocket | Supports bidirectional updates VAYLET does not need; browser upgrade cannot set arbitrary bearer headers through native WebSocket, so would need a separate secure authenticated handshake/ticket, proxy upgrade and per-replica lifecycle management. | **Reject for first release** absent compelling measured advantage |
| Authenticated conditional **long-poll** using ordinary `fetch`, with server wake on scoped invalidation and bounded 15–25 s hold. | Avoids SSE buffering constraints and shares bearer/retry plumbing; increases request churn and still needs distributed fan-out, server admission limits, cancel-on-revoke and timeout policy. | **Fallback candidate only if SSE fails T0**; must separately prove 3 s and load |
| Fixed 1–2 s per-tab SQL polling; or client-only `BroadcastChannel` messages | Multiplies expensive source queries; local tab messages cannot distribute committed events across API processes or clients. | **Reject** as the primary channel |

Both SSE and long-poll should use a **scoped invalidation protocol**, not raw notifications: `invalidate` means “your authorized preview may have changed,” with bounded protocol version, event kind and optional opaque monotonic local hint. It carries no title, count, source ID, vehicle, person, location-specific confidential facts, token, audit/payment payload or user-specific Seen state. A false-positive hint is safe but expensive; a missed hint must be repaired by reconciliation. Only a new scoped preview GET may change the displayed count/list, including to zero.

## Future end-to-end data path (not implemented)

No current canonical source writer publishes a Management Alerts invalidation after commit. The source readers and preview are implemented, but code search at the running QA image revision found no Management Alerts publisher, PostgreSQL listener, generic alert outbox or post-commit dispatcher. Persisting a domain/audit event transactionally is **not** the same as publishing a realtime hint. The alternatives below are design candidates only; DEC-109/110/111 do not approve a transport, new writer hook, outbox, trigger, migration or worker.

1. For each relevant transaction, commit its canonical source state/event or its separately authorized alert mutation (Seen/preference) within that owning transaction. The invalidation for that mutation must be transaction-coupled: PostgreSQL `NOTIFY` issued **inside that same transaction**, or a previously approved transactional outbox with a post-commit dispatcher. PostgreSQL delivers transactional notifications only after successful COMMIT; a rollback produces no signal. **Do not publish from a pre-commit application callback or a best-effort post-COMMIT call** that can lose the event in a crash.
2. For multi-instance delivery, each API process has its **own** bounded dedicated PostgreSQL `LISTEN` connection for one fixed channel, independent of request transaction pools and included in the deployment's connection budget. The payload is a minimal internal routing hint with an explicit scope kind (`LOCATION` or `ORGANIZATION`), Organization ID, Location ID only for Location-scoped events, and event class; it carries no sensitive source data. Do not use dynamic per-tenant DB channel names. Listener restart, reconnection and missed-message accounting are mandatory. PostgreSQL `NOTIFY` is ephemeral, is **not** durable storage and does **not** provide replay; an API restart/failover or disconnected client may miss it.
3. Each replica coalesces matching internal hints for a small bounded interval (proposed starting point 100–250 ms, empirically tune) and applies separate audience routes:
   - **Location route:** Location-scoped categories fan out only to currently authorized clients whose selected active Location exactly matches the event Location and whose source authority permits that category.
   - **Organization route — ALT-15 only:** ALT-15 has `locationId: null` and owning-Organization scope. Its committed staff-security event MUST invalidate the ordinary Management Alerts bell for current protected Company Admins in that Organization, regardless of which Location is selected or whether one is selected at all. Reauthorize each recipient's current Staff session, CA role, protected MFA, Organization membership/entitlement and `TENANT_AUDIT_READ_ELIGIBLE` source authority; do not require or fabricate an ALT-15 Location grant/ID. The subsequent normal preview must use a separately authorized Organization-scoped path and return the occurrence without selected-Location dependency. Never fan it out to Location Managers.
   - **ALT-17 exclusion:** ALT-17 MUST NOT enter the ordinary Management Alerts event stream, invalidation fan-out, preview bell or restricted Dashboard shell. It belongs only in the separately authorized subscription-only utility while the effective entitlement restricts Dashboard access. It is not a Seen-eligible occurrence and has no seven-day attention window. Any future utility refresh channel requires its own explicit transport and authorization contract; it is not an Organization-bell route.

   No cross-tenant signal distribution to browsers. In particular, an Organization-scoped ALT-15 event must never be narrowed to whichever Location happened to commit it, and ALT-17 must never be treated as another Organization-only bell category.

   **Current-code P1 guardrail for ALT-17:** the ordinary unified source aggregator currently emits ALT-15 but not ALT-17, and the exact-source endpoint rejects ALT-17. However, generic ordinary-bell category/DTO schemas, the server correlator, client unified-preview decoder and downstream fan-out boundary must each reject an ALT-17-shaped candidate, including `locationId:null` when `allowOrganizationOnly` is true. The dedicated ALT-17 source-reader helper is not wired to a production route; the current subscription page instead renders localized restriction copy from its protected subscription read. Therefore no current ALT-17 bell emission was observed, but the ordinary-bell exclusion is not enforced at every generic boundary. Before any promotion, add explicit rejection at every schema/decoder/correlator/fan-out boundary, with negative tests injecting otherwise well-formed ALT-17 candidates. Keep the utility path separately authorized and never feed its result into the bell preview.

4. On receipt, the connected visible tab coalesces another preview request through the existing single-flight/transport lease and authority fence, then calls the current versioned API preview. A response is applied only if its **identity, exact Staff session, Organization, relevant source scope (selected Location for Location cases; Organization for ALT-15), selection generation and preference revision** still match. ALT-15 preview authorization must not require an active selected Location. A stream event is never authoritative source state.
5. On stream connect/reconnect, initial foreground, focus/resume, missed sequence, unknown disconnect or notification delivery failure, perform one freshly authorized snapshot. A slower safety read (existing 60 s foreground cadence as initial comparison) repairs loss; it is explicitly **not** a <=3 s guarantee during degraded transport.

**Publication approval gate (E1).** Map every relevant canonical writer: task/dispatch/retrieval transitions; incidents; payment outcome/reconciliation; force-end Shift; role/Location grant changes; Location intake; commercial entitlement; personal preference and Seen. Prove real committed event links and observed rollback with isolated PG17 transactions. Decide which exact writers may gain transaction-coupled notifications and whether any approved outbox already covers them. The current task grants **no source-writer, migration, trigger, worker or infrastructure changes**. Approval must include DB privilege, payload privacy, listener capacity, and source-specific retirement semantics. Without complete mapping, missing publishers cannot be claimed live.

## Lifecycle and authorization requirements

- Establish the ordinary bell stream only after current authenticated Staff session, Company Admin/LM audience, effective Dashboard entitlement and each applicable source authority are verified; maintain feature OFF gates. Location-scoped categories require their exact active selected Location. ALT-15 requires its separate Organization-scoped CA-only source authority and protected MFA, independent of selected Location. ALT-17 is excluded from this stream and ordinary bell. Resolve user and tenant from persisted Staff session, not request body, query string, client-selected Location or event payload. Scoped delivery may also need selective source reauthorization before an invalidate is emitted; any downstream GET always reauthorizes each source.
- Use same-origin HTTPS `fetch` with `Authorization: Bearer` header; **never** put bearer tokens, one-time tokens or session IDs in an SSE/WebSocket URL, query, log or DOM. Keep `Cache-Control: no-store`, disable proxy buffering where supported and verify actual headers. A standalone `EventSource` is incompatible with the existing bearer-in-header contract unless a separately approved safe authenticated proxy exists.
- Do not stretch a privileged request across an unbounded session. Apply a finite stream lease (proposed 15–30 s), idle/heartbeat cap, server-side session/grant/entitlement recheck before sending each scoped hint and on lease renewal, plus best-effort immediate revocation signaling. A new request after revocation must fail; a previously authorized bounded response may complete under Accepted **DEC-108:18-45**. Activity-neutral reads/stream maintenance may **not** refresh Company Admin idle MFA, unlock expired assurance or transform transient loss into zero.
- Close stream and abort/retire pending GET on logout, User disable, role/location revocation, MFA/entitlement loss, scope change, A→B→A, preference revision, hidden/offline/unmount or definitive authorization denial. The **generation must advance monotonically**; a stale A event or non-cooperative A request cannot repaint new A after intervening B. Open-dropdown and bell use one same scoped preview owner. Other tabs cannot grant authority; cross-tab broadcast (if introduced) carries a hint only and each tab validates its own current session/scope.
- Reconnect with bounded exponential backoff and jitter, e.g. 1/2/4/8/16/30 s cap, only while visible/online and currently authorized; respect `Retry-After` when provided. A 401/403/MFA/entitlement/invalid-protocol response suspends until explicit user recovery; 429/5xx/timeouts show **unavailable**, preserve no stale authoritative zero and use bounded retry. Never overlap auth refresh and old-identity stream send.
- **User-owned invalidation across devices:** a committed Seen receipt is owned by `(Organization, User, category, occurrence)`. Its invalidation must reach every active tab/device for that same User+Organization so the same user's unseen set converges everywhere; it must not invalidate another user's Seen state. A changed timing-preference revision is likewise owned by `(Organization, User)` and must refresh that user's active devices only. Source-condition changes use their source scope and fan out to currently authorized recipients. Same-browser `BroadcastChannel` may accelerate local tabs but cannot satisfy cross-device delivery; every receiving device reauthorizes its own session and fetches a fresh preview. Internal routing may carry the minimum owner scope, but browser messages contain only an invalidation hint and never User IDs, receipt keys, preferences or alert payloads.
- Limit concurrent streams per API process, pending invalidations and per-scope buffered hints; close idle/slow readers, cap bytes/events and pending queue, and implement clean shutdown/drain. HTTP metrics currently report `finish`/`close`; stream duration should not be mistaken for normal request latency. Reserve database capacity for each LISTEN connection without claiming an unconstrained extra pool.
