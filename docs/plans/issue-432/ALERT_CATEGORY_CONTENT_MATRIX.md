# Issue #432 — Management alert content matrix (proposal, no activation)

**Status: planning only; source-inspected at baseline `a9c1c06c`.** This file specifies copy and the minimal facts required by the owner's Issue #432 UI-02 addendum. **CURRENT** means a behavior/field observed in this checkout; **PROPOSED** means no runtime support is implied. The inventory contains 16 in-scope candidate IDs: 15 ordinary-bell categories (`ALT-01..13`, `ALT-15`, `ALT-16`) plus ALT-17 for the restricted subscription utility only. ALT-14 is excluded. These are not activation claims; the feature gates remain OFF. This plan does not amend DEC-109/110/111 or authorize rollout.

## Current content limitations and invariants

- **CURRENT:** Phase-1 `/preview` has `id, category, severity, sourceKind, sourceId, episodeId, locationId, occurredAt, title`; Phase-2/3 `/preview-unified` adds `caseKind`, nullable ACTIVE `occurredAt`, and unseen OCCURRENCE flags. Neither schema contains a description, human-readable location name, source status/subtype, or destination. `management-alert-preview.ts:22-81`; `management-alert-unified-preview.ts:52-154`.
- **CURRENT:** Phase-1 renders source-provided English titles verbatim even in Arabic; the unified list translates only a **closed subset** of exact English titles in `alert-unified-title.ts:9-30`. The unified list prominently exposes category IDs and generic “Current condition” / “Committed occurrence” metadata, with a separate detail button (`alert-unified-list.tsx:50-100`). The legacy Phase-1 exact-source `FocusDialog` also visibly prints `category/sourceId` and `episodeId` (`alert-exact-source-dialog.tsx:131-143`); do not copy those raw identifiers into the proposed v2 display. Incident titles are currently only `Critical incident` or `Important incident` (`incident-alert-reader.ts:24-55`).
- **PROPOSED:** Render **localized** title and one factual description, each derived from a closed category/subtype/status mapping over the **authorized** source projection. Never interpolate free-form source text, narrative, customer, staff, vehicle, account, provider reference, coordinates or raw internal IDs. Show selected authorized Location context only from the currently checked scope or a separately authorized minimal Location label. `occurredAt` is *event/eligibility source time*, not a promise that a condition began then; when null, omit time or label “Current status · start time not recorded”.
- **CURRENT semantics preserved:** Source order, CRITICAL versus IMPORTANT, capped 20 items plus `hasMore`, suppression/correlation, no authoritative zero on failed reads, source-specific authorization before count/LIMIT, and no marking Seen on opening/clicking an ACTIVE row. For OCCURRENCE, Seen is a separate explicit per-user action after server confirmation. See DEC-109 OD-05, DEC-110 OD-07A/C, DEC-111 OD-08, and `management-alert-unified-preview.ts:64-139`.

## Fact sourcing and copy release gates

1. **ALT-08:** Current incident query selects only `incident.id`, `severity`, and `created_at` after filtering status, so a dynamic `OPEN`/`INVESTIGATING` description requires projecting persisted `incident.status` through a tightly scoped source read. Do **not** use `incidents.description`, raw type, photos, narrative, or reporter/person. If projection is not ready, use neutral copy “An incident at this Location currently needs attention” / “يوجد حادث في هذا الموقع يحتاج متابعة حاليًا”, with only already-proven severity in the title.
2. **ALT-02/03, ALT-07, ALT-09, ALT-15:** Each source reader internally distinguishes type or subtype, but the public item currently projects only a `title` English string. Do not infer subtype by English-text matching. Add closed `taskType`, `handoffEventKind`, `geofenceSubtype`, or `staffEventKind` codes **only where needed** and authorize before projection. For ALT-09, `recorded_at` is attention time; `captured_at` is a different clock and must not be conflated.
3. **ALT-04, ALT-06, ALT-10/11:** Existing timestamps are authoritative for the current reader's eligibility/operation, not necessarily the moment a user saw the alert. Do not label them “notification delivered at”. ALT-16 has `occurredAt:null` in unified detail and no stopped-since proof. Never fabricate one. Time-driven eligibility must update without requiring another writer, per Issue #432 RT-01.
4. **ALT-05/07/09/13/15:** Committed **OCCURRENCE** rows are the only Seen-eligible categories; Seen is a separate explicit per-user action after source/role/MFA reauthorization and server confirmation. After Seen the row leaves the user's pending preview; the source event still exists. Do not turn row-click, read, popover open or navigation into Seen. **P1 boundary mismatch:** current list readers include the exact seven-day equality boundary (`attentionAt >= now - 7 days`), while `management-alert-seen-repository.ts:45-46,55-60` requires `now < occurredAt + 7 days` for both insert and idempotent retry. At equality a row can still be returned with `seenEligible=true` but the Seen PUT rejects. DEC-110 says “within seven days” without choosing equality; do not assume either comparator. Align list visibility, `seenEligible`, Seen insert and retry after the boundary is explicitly resolved. Do not claim the visible row can always be marked Seen at the boundary.
5. **ALT-17:** The restriction copy is already rendered as a subscription-only status on `/billing-subscription`. No generic Dashboard bell, ALT-17 detail endpoint, Seen, escalation, or normal Dashboard source navigation. Exact effective entitlement and CA session/MFA remain prerequisites.
6. **Evidence boundary:** This is static source inspection, not a proof run. DEC-109/110/111 leave chronology, stage-clock, occurrence grouping, Seen concurrency/retirement, PostgreSQL 17, mounted HTTP, browser, performance and release gates open. In particular, ALT-02/03 same-millisecond chronology, ALT-04/06 stage-entry chronology, ALT-05 DEC-107 compatibility, and ALT-07/09 occurrence identity/grouping still require their accepted source-specific evidence before activation.

**Review condition:** every displayed assertion must have an inspected persisted field, allowlisted subtype, authorized source scope (Location or Organization) and a verified read path. Validate English/Arabic, RTL/LTR and narrow popover, especially long incident and role labels; verify no category code or raw UUID is the primary visible content.
