## Shared A/B visual contract (proposed alert-local changes)

1. **Bell** — Use the prototype-only borderless UI-01 treatment above. Keep a 44×44 target, 18px glyph, count styling, original topbar slot and visible `:focus-visible` ring. Count remains a distinct, tightly aligned small indicator. Show valid confirmed **0, 1, 9, 12, 20+** and unknown **—** legibly; the number is synthetic in this prototype and must not be mistaken for a live server-authoritative count. No pulsing, gradients, glow or sound.
2. **Popover anchor** — Attach the card to the *live* bell trigger's **logical trailing edge**: right in EN/LTR, left in AR/RTL; top edge follows bell bottom by **8px**. The current shared `useAlertPanelGeometry` computes identical A/B geometry: width `min(416px, visualViewport.width - 32px)`, **16px** visual-viewport side inset, **8px** anchor gap, and max height `floor(min(544px, 72% of visualViewport.height, available vertical space))`. It uses the available space above/below the anchor and can reposition above when the lower space is insufficient. The alert list scrolls independently while header/footer remain available. Use `--surface`, 1px `--border`, 12px radius and `--shadow` with no glass, blur, dark backdrop, screen centering or blocking layer.
3. **Layering** — Because `.shell-main` has `overflow:hidden`, an anchored, collision-aware portal or equivalent verified non-clipped strategy is needed. Keep the popover above Dashboard content and inside the viewport, but below modal/backdrop layers and coordinated with neighboring overlays. Bell stays in normal `topbar-actions` flow.
4. **Header** — Start-aligned localized heading "Important & critical alerts" / "التنبيهات المهمة والحرجة" at about **16–18px / 600–700**, optional restrained count/status and a trailing plain Close action. Horizontal inset **16px**, vertical inset **12–16px**, bottom 1px `--border` divider. Text must not displace the shell. Keep list scroll within popover, never clip the only visible Close/Retry controls.
5. **Rows** — Most urgent/recent order **only as returned authoritatively**. Use clear hierarchy: narrow colored severity cue **plus text**, localized factual title in `--text`, short approved description, optional authorized Location/source label, trustworthy time only if recorded. `ALT-08`, "Source ALT-08", "Current condition" must not dominate the row. A current condition with unknown onset time gets localized explicit "time unavailable"; there is no invented "just now", "5 min ago", vehicle/person/incident type, or event narrative. `min-inline-size:0`, `overflow-wrap:anywhere`, `<bdi>` isolate mixed IDs/labels.
6. **Interactions** — The ALT-08 sample uses one native local title/description anchor to the fixed synthetic fragment `#SIM-TARGET-INCIDENT-1042`, opening an in-memory destination with explicit source/target IDs and `No production record`. Browser hash reload/new tab, Back/Forward, and distinct unavailable/missing/unauthorized states are covered by final E2E. This never navigates to a production record. Eligible OCCURRENCE Seen is a separate >=44px action; ACTIVE never Seen. Pointer-open first Tab enters once; Shift+Tab from first panel control returns to bell while the panel stays open, the next forward Tab exits/closes. Immediate keyboard Enter→Tab with geometry held by RAF safely defers entry. Seen success next eligible→nearest preceding eligible→Close/panel heading; failure returns to same-row retry. Final four-spec headless **8/8 PASS** and headed/debug **8/8 PASS** validate exercised synthetic interactions. Production exact-source links remain unavailable pending route, source re-read and target by-ID authorization.
7. **States** — Distinguish confirmed empty (**0**), one case, many cases, top **20 + hasMore** (**20+**), loading/slow, stale/unavailable (**—** or clearly last confirmed count with age), definitive access loss, and reconnecting/offline. Unknown/error must never become an authoritative 0. Preserve shell control alignment in every state and keep panel open when authorized live data changes. The prototype's synthetic scenarios must be labeled synthetic, including displayed time and navigation destination.
8. **Accessibility and motion** — Bell `aria-expanded` and localized name/status; panel a non-modal labelled region/list, **not** `role=menu` or a modal dialog. Escape closes and returns focus to the still-mounted bell; outside pointer closes without stealing focus; Tab remains natural. No keyboard trap, pressed-only priority, or focus loss when an item vanishes. Use reduced motion and supported forced-colors behavior. Full event-by-event acceptance is specified separately in `ACCESSIBILITY_AND_INTERACTION_SPEC.md`.
