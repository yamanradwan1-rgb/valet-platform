### Existing implementation patterns

Verified literal controller prefixes include v1/staff/valet-sessions in StartParkingController and v1/staff/shifts in ShiftController. There is no basis for inventing an /api prefix. Controllers resolve the existing staff principal, reject ambiguous duplicate Authorization headers, validate shared schemas, run named operations, and delegate to transaction-aware commands. Runtime commands use PostgresTransaction/raw SQL, not an invented Prisma Client mutation/error path.

Operational authority is current persisted user/membership/Organization/Location/access plus operation-specific ownership and Shift eligibility. Management authority is different: Company Admin management capability/MFA and Location Manager exact-Location configuration paths cannot be substituted for field-task ownership. ORG_ADMIN is not an automatic operational supervisor.

Partial unique indexes, check constraints, security-definer management functions and runtime grants exist in forward SQL migrations beyond what Prisma alone expresses. Audit writers are typed boundaries: Shift audit and custody audit are not interchangeable merely because AuditEvent permits nullable session IDs.
