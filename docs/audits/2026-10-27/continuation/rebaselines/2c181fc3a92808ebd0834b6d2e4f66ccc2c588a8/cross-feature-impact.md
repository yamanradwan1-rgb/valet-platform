# Current-main cross-feature impact assessment

This is a targeted dependency assessment at main `2c181fc3a92808ebd0834b6d2e4f66ccc2c588a8`, not a completed integration audit.

1. **Pool and database lifecycle:** `postgres.ts` constructs the changed `boundPostgresPool`, which wraps connection acquisition, lease setup/reset/disposal, deadlines and query timeout classification. All services injected with `RUNTIME_POSTGRES_POOL` inherit the new failure/availability behavior (authentication, check-in, dispatch, payments, dashboard, guest flows and background maintenance). Revalidate admission and waiter caps, leased-client destruction, rollback/commit unknown outcomes, pool-closing behavior and HTTP error mapping under contention. No claimed load-test speedup is independently measured.
2. **HTTP request diagnostics:** `main.ts` installs the changed `http-metrics.middleware.ts`; `api-operation-runner.ts` records mapped failures and guest database deadlines. The newly added diagnostic formatter emits only fixed route templates, allowlisted mapped error codes/reasons and request IDs. The unchanged `api-request.ts` restricts external request IDs to 1–128 ASCII `[A-Za-z0-9._-]` characters. Confirm real middleware/filter ordering, 499 disconnect semantics, 401/403/429/5xx mapping, logging overhead and no sensitive URI/query/PII leakage via targeted tests.
3. **Operational-context batching:** `staff-operational-context.service.ts` delegates to the changed query, which now batches membership pairs via `unnest` and joins organization/location scope per pair. The new details helper preserves unconditional active shift existence checks and projects only active, authorized locations. The response shape appears unchanged by static comparison; verify revoked grants, membership/shift races, multi-org scope, cross-tenant denial, duplicate active shifts, null vs denied semantics and query-count behavior with database-backed fixtures.
4. **Historical review interaction:** one C009 provisional timeline controller directly consumes the modified DB module and API runner. Six C008 provisional Dashboard E2E files exercise authority, roles, scope restoration or help context that transitively depend on the modified staff query. Their saved reviews remain valid descriptions of their unchanged source bytes, but updated cross-component behavior has not been proven by fresh test execution.

It is a prioritized subset, not proof that every indirect consumer was exhaustively revalidated. No P0/P1 was confirmed during source rebaseline. Source-only hypotheses must not be promoted to exploit or production conclusions without appropriate validation.
