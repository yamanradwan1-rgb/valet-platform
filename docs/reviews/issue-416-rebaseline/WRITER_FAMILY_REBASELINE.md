## Verification and prioritization caveats

**Current source reachability is not an actual exploit.** We verified a call path for A01/A02/M01–M03 and registered MFA; effective runtime roles, inherited PUBLIC EXECUTE, SQL definer environment and provisioner replay need **new isolated PG17 actual-role probes**. Future lower-priority M08–M13/X01 dispositions must be revisited if the function can mutate tenant authority or customer custody. Under Option C Reset's R01/R02/R03 remain unregistered/OFF, so they are **not launch blockers by exposure**; no broad claim of 35 safe-to-defer paths is made.

**What disappears if C is approved:** no current need to finish R01/R02/R03, six reset quotas, Reset UI activation, universal VAP1 proof protocol, migration113 W9 recovery or the entire 210-case Option A suite. **What does not disappear:** all demonstrable T5 Auth/MFA/role bypasses; tenant isolation; current Staff/Guest compatibility; immutable sensitive audit; API-authenticated and DB privilege correctness; same-SHA CI and independent release acceptance.
