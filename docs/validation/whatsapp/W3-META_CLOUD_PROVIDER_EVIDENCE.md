# W3 — Meta Cloud API provider boundary

## Frozen scope and integration

Code owner: W3, `feat/wa-w3-meta`, base `a087ad38cb249840389e5aefaefbecb47333373f`.
This is an **OFF-by-default, synthetic/mock-only** adapter. No actual Meta account, number, template, recipient, credential or physical device was tested. The `OutboundProvider` and `OutboundSendInput` interfaces remain unchanged.

Prime/W4 inject `createMetaCloudProvider({ resolveAuthorizedAttempt, mode, globallyEnabled, fetchImpl? })` from `apps/api/src/modules/notifications/providers/meta-cloud-provider.ts`. Default `mode=disabled` and `globallyEnabled=false` prevent network calls. Only sender bootstrap can set `globallyEnabled` after durable global kill switch, current consent/withdrawal, authorized tenant/location binding, budget, expiry, generation and committed attempt-marker fences. A reusable `attemptHandle` is **not** HTTP idempotency: a second call after uncertainty is prohibited by W4.

`resolveAuthorizedAttempt(attemptHandle)` must resolve the **actual immutable committed attempt** from trusted server state; return `null` on unauthorized, expired, revoked, wrong tenant, missing evidence, mismatched policy/binding/version, or disabled account. It must retrieve the Organization-owned WABA + Phone Number ID, server-held bearer token, approved template record, canonical Customer origin and exact test recipient allowlist. No client can choose account, bearer or template. Its result must be current at dispatch; `OutboundSendInput` is verified against it. Neither bearer nor account secret appears in DB policy projection, browser or logs. Wire an audited Meta connection/onboarding and secret-rotation resolver separately; W3 does not invent one.

`ApprovedMetaTemplate` is a server-sourced, verified approval record, scoped to the **same WABA**. Strict allowed language pairs: `ar -> ar` and `en -> en_US`. Only `BODY_ONE_URL` with exactly one URL text parameter is emitted; no dynamic template names, free text, interactive controls or remote media. The catalog `catalogVersion` is controlled by server policy/immutable attempt; adapter validates approved name, language and WABA on every send. No synthetic template fixture constitutes an approved production template.

The Meta Graph origin is fixed to `https://graph.facebook.com`, API path exactly `/v26.0/{numeric Phone Number ID}/messages`. Input `graphVersion` must equal pinned `v26.0`. POST uses JSON + Bearer, `redirect:'error'`, one fetch call and an abort after 10 seconds; response body cap 8 KiB. All transport errors, timeouts, malformed/truncated success, unrecognized provider error and uncertain 5xx are `UNKNOWN` (W4 MUST NOT replay). Only allowlisted Meta error codes produce permanent rejection, or `130429`/`80007` with HTTP 400/429 produces `NOT_ACCEPTED` rate limit. Response `wamid.*` means request accepted for processing, **not** delivered/read.

`biz_opaque_callback_data` is set to the random immutable `attemptHandle`, maximum 512 characters, and is intended to permit a callback-first status lookup when the accepted HTTP response was lost; independently require WABA + Phone Number ID + recipient-digest binding and valid signature. A matching `wamid` is also correlated against stored attempt+binding; neither handle alone nor callback payload alone chooses a tenant. The exact opaque echo support is not independently proven by a current Meta-owned schema and therefore remains a live validation gate.

2. Official Meta-owned webhook payload reference: <https://www.postman.com/meta/whatsapp-business-platform/folder/tduohwq/webhook-payload-reference>. `object=whatsapp_business_account`, `entry[].id` WABA, `changes[].field=messages`, `value.metadata.phone_number_id`, and `statuses` values `sent`, `delivered`, `read`, `failed`. WABA subscription details: <https://www.postman.com/meta/whatsapp-business-platform/folder/ozgs3jn/webhook-subscriptions>.
3. Archived Meta WhatsApp Node SDK webhook reference: <https://whatsapp.github.io/WhatsApp-Nodejs-SDK/api-reference/webhooks/start/>. GET verification token/challenge and POST `x-hub-signature-256` HMAC with app secret are documented, but this SDK is archived (2023); recheck current developer specification before deployment.
4. Graph version listing mirror of Meta's changelog (original official developer endpoint was blocked by HTTP 429): <https://hattasimae.online/?_=%2Fdocs%2Fgraph-api%2Fchangelog%235zAtP5u4ZU%2Fbs9epEK83o%2F03dymJ4S8C0LnK4h%2BvKg%3D%3D> shows `v26.0` released 2026-07-29 and current as of this review. Direct official original: <https://developers.facebook.com/docs/graph-api/changelog/> — **not fetched** due Meta rate limits. Version compatibility with WhatsApp message endpoint still requires official confirmation and test-number validation.
5. Reproduced WhatsApp Cloud API error-code documentation <https://github.com/kapso-meta-docs/documentation/blob/main/documentation/whatsapp/error-codes.mdx> lists `80007` and `130429` rate limits with HTTP **400**, `132001` unapproved/missing template with HTTP 404, and `132000` malformed template parameters with HTTP 400. This mirror is not an authenticated live provider result; exact classifications still need test-account verification.

## Real activation blockers

- Verify approved exact AR/EN template name, locale, component layout, classification, WABA ownership and per-company registration status from actual Meta account; do not permit a generic fixture name. Prove Meta preserves `#guestToken=` exactly in a real template recipient's opened browser; no live sends or fragment retention test occurred.
- Verify `biz_opaque_callback_data` echoed on send-status callbacks and supported under `v26.0`; verify response and error codes, expected rate limit mapping, complete raw webhook signature/schema and provider retry horizon directly from current Meta docs and controlled test account.
- Verify authenticated company onboarding, secret alias/rotation, test number allowlist and verified opt-in/withdrawal; global and durable send controls stay OFF until explicit separate authorization. No production sender, Meta token, or tenant credential is configured here.
- Prime must register `whatsapp-provider-*` tests in the standard non-Postgres classifier and wire the sender resolver. W3 owns no `app.module`, `main.ts`, worker, schema, flags or deployment wiring.
