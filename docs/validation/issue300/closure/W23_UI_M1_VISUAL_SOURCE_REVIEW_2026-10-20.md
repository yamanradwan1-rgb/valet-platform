## Source/evidence findings

1. **Missing screenshot baseline provenance:** G0 `FROZEN_UI_MANIFEST.json:7` has a `snapshotReference` pointing to `D:/kndoom/valet-platform/tmp/issue-300-concept-a-ui-integration/apps/dashboard/test-results/issue300-concept-a-ui`, which was **not found** during this review. The G0 file's 124 source SHA hashes cannot be used as PNG visual references. The baseline scenario path is independently configurable (`issue300-closure.spec.ts:36-49,285-297`), with no pinned baseline PNG SHA manifest, candidate/fixture metadata, or snapshot provenance check in this comparison. A self-selected image directory could accidentally compare against the wrong baseline. Therefore a passing image hash without provenance would still be insufficient.
2. **UI-M1 visual coverage narrower than UI01–UI06:** The 32 screenshot tests only open the authorized Investigation form, set locale/theme/zoom, check form visibility and page horizontal overflow, then capture the image (`issue300-closure.spec.ts:264-299`). They do not trigger `Apply`, `Load more Sessions`, `Load more events`, oversized employee selector/refinement, DST fold/gap choice, partial coverage warnings, or detail/failure states. Those states need separate same-fixture baseline captures and visual assertions before broad UI-M1 visual acceptance can be claimed.
3. **Earlier CSS zoom example is not native browser-zoom evidence:** `apps/dashboard/e2e/issue300-original-shell-zoom-baseline.spec.ts:25-39` sets `document.documentElement.style.zoom = "2"` with synthetic fixtures. The R2 32-case source attempts native browser shortcuts and checks effective viewport reduction at `issue300-closure.spec.ts:108-127`; neither source proves that 200% zoom actually ran or passed on this candidate.
4. **Skip is not acceptance:** `issue300-closure.spec.ts:69-74` skips each case when the exact real prerequisite or single-case title is absent. A successful test discovery or skipped test exit code cannot be treated as 34 successful authentic browser executions.
