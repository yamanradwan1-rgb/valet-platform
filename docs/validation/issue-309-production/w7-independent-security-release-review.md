# Issue #309 — independent read-only security and release review (W7)

Review base: `459e9c42dfff5b2aeb11ee9165a7d1a4338a7783` (main, after #315). Owner-approved design: `a6227f681f4948305c331b1372062fe34533b9aa` with HTML SHA-256 beginning `0b190089`. Audit scope: W3 authorization, W4 dashboard API, W2 React, storage/upload isolation, independent QA. This is a source review, not a deployed S3/provider test or permission approval.

## Binding security contract

1. **No default VIEW right.** DEC-104 (`docs/decisions/DEC-104_VERIFIED_CONDITION_PHOTO_BYTE_EVIDENCE.md:20-28,55-60`) authorized verified private-byte **upload**, not Dashboard gallery access. The W3 design document (`docs/validation/issue-309-prototype/security-and-access-questions.md:17-49` on `design/issue-309-w3-security`) proposes CA/LM only; questions Q309-01... remain owner decisions. Any runtime VIEW must stay denied until the explicit policy is accepted. Employee, Supervisor, Guest, cross-tenant and support identities gain no implicit rights.
2. **Exact scope.** Check current credential, Staff token/session, user, role and entitlement, Organization, active Location and explicit LM Location access, then persisted ValetSession `(organization_id, location_id, id)`. A Vehicle ID alone is never a valid binding. Distinguish inactive scope, historical session and photo availability.
3. **Canonical evidence only.** `apps/api/src/modules/valet-sessions/condition-photo-qualified-receipt.ts:41-103` selects only exact-scoped purpose `CHECK_IN_CONDITION`, verified operation, selected attempt, matching content digest/size and `AVAILABLE` verification, bounded to 10. No client-supplied S3 key/bucket/version may enter the selector. `s3-private-photo-store.ts:89-110` provides bounded exact-version S3 read; caller must reject missing version, wrong bucket alias, wrong exact object version, size or SHA256. Never emit keys, bucket, digest or attempts in API DTOs.
4. **#315 compatible revocation.** Current source `live-history-read-authorization.ts:18-55,72-116,140-213,215-287` holds shared staff-user and exact session locks, then current CA MFA, shared staff-management Organization advisory, entitlement/membership/location/grant row locks. `dashboard-read-authorization.ts:41-85` explains canonical staff-management lock and a second READ COMMITTED check. Protected photo reads need short pre-S3 and post-S3 authorization, no S3 I/O while holding a DB transaction, and an explicit last authorization/availability serialization point before returning bytes.
5. **Private delivery, browser lifetime and retention.** Send authenticated `image/jpeg` via API with `Cache-Control: no-store` and `X-Content-Type-Options: nosniff`, no signed/public URL and no identity-bearing logs. Abort pending reads, revoke every generated Blob URL on close/unmount/identity or Location switch, and ensure stale responses cannot populate a new drawer. Existing evidence/holds/orphan-only maintenance and upload/DB contracts stay untouched.

## Test matrix required to declare production-ready

- **Privilege defaults:** no policy accepted / disabled; CA with and without active MFA; LM grant present/removed; Supervisor, Employee, Guest, support, inactive user/membership/org/location/subscription; stale/expired Staff token.
- **BOLA:** wrong Organization, Location, Session, photo UUID; two visits from same Vehicle; photo from another session in one Location; metadata-only legacy, failed/pending verification and unavailable state.
- **Revocation timing:** canonical LM grant writer-first and reader-first, two simultaneous reads, role change, session logout/refresh, CA MFA factor revocation during both preflight and S3; post-I/O deny and failure response no leaks. Confirm #315 lock order/no deadlock and that no connection holds locks across S3.
- **Object correctness:** missing object/version, wrong returned VersionId, wrong bucket alias, digest mismatch, size mismatch, provider timeout/abort, `AVAILABLE` -> `UNAVAILABLE` during read, duplicate/ambiguous IDs, request budget and rate/concurrency enforcement.
- **Client lifecycle:** close drawer while fetch pending, switch Session/Location/Organization and logout, repeated open/close, oversized/malformed JPEG, keyboard modal focus/escape/restore and dual EN/AR theme/viewport. Verify raw image bytes/keys/photo IDs do not enter telemetry or offline/durable caches.
- **Regression:** `git diff --name-only 459e9c42..candidate` must preserve Native, uploader, database migration/schema, qualification and private-store contracts, original Dashboard Facts/Help/Close geometry and unrelated sections. Run focused API negative/concurrency tests, source contracts, browser and UI-FROZEN parity.
