## Coverage and counting contract

The route universe is the registered DashboardModule and ManagementModule controller GET handlers, including the seven inherited Shift Presence GET decorators mounted once under the Dashboard Location Manager prefix and once under the Management Company Admin prefix. This yields **85 concrete GET route patterns: Dashboard 40 + Management 45**, from **78 distinct @Get declarations + 7 additional inherited mounts**. There are **zero explicit @Head declarations** in these controller trees. Nest's default Express GET-to-HEAD handling may accept corresponding HEAD requests; no separate HEAD behavior, body/stream side effect, or 85-case HTTP HEAD test was established. HEAD is therefore a conditional read alias, never counted as another verified route.

The matrix enumerates every concrete GET pattern in these two registered modules. POST report exports are read-producing commands with audit mutations and are listed separately, not included in the 85. Four additional Dashboard-facing Staff operational APIs (vehicle directory, session detail, live map, route history) are separately enumerated: **85 core module routes + 4 adjacent operational routes = 89 explicitly inspected GET patterns**. The 89 is an exact count of this declared review universe, not of all staff/API routes. There may be other non-Dashboard API reads elsewhere in the monolith; this is not an inventory of every API endpoint.

Source refs are exact file:line relative to apps/api/src/modules/ unless prefixed with another root. The @Get decorator line is the route declaration; the companion entrypoint is the service or query location. Most controllers call STAFF_SESSION_CONTEXT_RESOLVER.resolve before the service transaction (auth/staff-session-context.ts:42-75); a resolved bearer outside that transaction is not by itself a held revocation lock. Tx means inPostgresTransaction on one connection unless stated. RC = PostgreSQL READ COMMITTED; RR = REPEATABLE READ.
