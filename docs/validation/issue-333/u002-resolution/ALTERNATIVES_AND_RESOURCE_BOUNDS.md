# U-002 alternatives, dependency map and resource bounds

Status: engineering alternatives only; none Accepted or implemented. Baseline: `9079706ad322e87f6f33fb61335fdc3b6bfd2528`. The governing hard case is a live API replica A, isolated from its database/coordinator but still able to emit bytes to its existing HTTP client; canonical writer B must decide whether it can COMMIT.

## Architecture alternatives

| Mechanism | Linearization / durable authority | New-reader admission and old-reader terminal witness | Partition / connection failure | Resource, deadlock and verdict |
| --- | --- | --- | --- | --- |
| Existing Organization advisory lock | PostgreSQL transaction lock, released at transaction or backend end | Blocks only compatible SQL lock takers while backend remains; does not cover Node HTTP | L-001 demonstrated lock lost while Node retained socket; TTL/watchdog backend loss breaks guarantee | C-001 max4 pool exhaustion under held response; SHARED→EXCLUSIVE `40P01`. **REJECTED as sole response fence** |
| Cluster-wide in-memory tickets | Coordinator-memory admission ordering; no durable authority across failover | Fence new entrants while coordinator healthy; terminal ACK from API needed | A may miss cancellation yet keep sending; coordinator restart loses tickets | Low DB pool use, but availability/correctness unproven. **REJECTED as sufficient** |
| Durable tickets / authorization epoch | Durable atomic gate/ticket/epoch in PostgreSQL or equivalent | Can serialize admissions with writer and persist state; cannot by itself prove HTTP socket stopped | Missed heartbeat, lease expiry, unknown ACK can mark a still-live emitter "dead" | Requires approved persistence and operation semantics; **CONDITIONALLY USEFUL, NOT SUFFICIENT** |
| Cross-instance cancellation + acknowledged terminal | Writer fence orders cancellation and waits for HTTP owner terminal response confirmation | Valid ACK must derive from actual terminal transport state; all old responses must report | Unreachable live A cannot ACK; timeout ≠ terminal | Bounded network/queue if all healthy; with partition either indefinite writer wait or unsafe COMMIT. **NOT SUFFICIENT without enforced egress fencing** |
| Buffer whole JSON + final grant recheck | Per-reader recheck immediately before calling `res.send` | Can reject before first byte; unlocked recheck-to-write gap remains | A can be partitioned after check; backend loss does not kill socket | Memory O(total pending response bytes), backpressure; **REJECTED alone** |
| Buffer + shared delivery fence held through terminal | Atomic fence across admission and last protected write (conceptual) | Could establish ordering if fence cannot disappear while socket remains live | PG session lease falsified; in-memory token can be forgotten; partitioned A keeps socket | Needs transport-aware, failure-safe egress enforcement; **CONDITIONAL** |
| Trusted process kill | OS/supervisor force-terminates verified API process before writer COMMIT | Proof must include all established protected sockets **and buffered protected bytes**; process cannot restart on stale scope | Kill-command ACK can be lost/forged; PID reuse, partitions, queued kernel/proxy bytes may still finish delivery | Risk of collateral availability/entire API restart; **CONDITIONAL on nonbypassable positive proof**, never sufficient alone |
| Ingress/network egress quarantine | Trustworthy last server-controlled hop prevents A→client protected writes; acknowledged fencing point | Could replace A's missing terminal ACK if old TCP/TLS connections and **queued protected payloads** are terminated/discarded with a final positive witness | Mere LB weight/drain or ingress disconnection fails if A has direct/writeable established socket; a proxy may itself have queued bytes | Requires new infrastructure/failure-domain guarantees, bounded kill/ack, validation. **UNVERIFIED potential necessity** |
| Whole-response fail-closed denial | Before first protected byte, deny stale or uncertain scope | If data already started, must verifiably abort remaining writes | Cannot retract protected prefix; remotely partitioned A may ignore abort | Strong containment when **pre-byte** and response-fenced; not sole distributed solution |
| Complete retained-scope recomputation | Current persisted authorization and entire C1/C2/C3 SQL projection under B-only scope | Recompute counts/latest/vehicle/cursors; still requires final transport fence | Fresh SQL alone does not close post-query gap | Expensive correlated history queries and O(response) buffer; **CONDITIONAL privacy policy** |
| Writer blocks until terminal ACK | Writer fence before COMMIT, no timeout-to-safe inference | Correct if admission is atomic and every response eventually positively terminates | Live partition or stalled reader may block indefinitely | Could preserve ordinary revoke safety but conflicts with DEC-081 immediacy; **NOT ACCEPTABLE as general emergency solution** |
| Unknown PostgreSQL COMMIT reconciliation | DB persisted CAS/audit/operation outcomes are authoritative | Retain closed admission, re-query canonical grant and security state; do not reopen on transport error alone | Caller may see failed HTTP while COMMIT succeeded; replay must not restore access | Needs current idempotence/CAS semantics, avoid new contracts without approval; **REQUIRED regardless of option** |

A **single trusted egress enforcer** must cover the same set of replicas/sockets the coordinator may misclassify as missing. This is an infrastructure premise requiring proof, not a property conferred by adding a database table. A gateway that observes only new connection admission is insufficient.

## Concurrency and failure-order budget

- **Lock ordering:** Avoid SHARED-to-EXCLUSIVE acquisition on the same advisory key; real `40P01` occurred in the Issue333 W5 experiment. Any future cross-domain locking mechanism must first define and test a total acquisition order for the exact chosen Organization/membership/User/Location keys and concurrent writers; no new key family or order is Accepted here. Current revoke Organization and security-disable User locks are distinct, so merely reusing one leaves gaps.
- **DB connections:** Holding a response's dedicated PostgreSQL connection to `finish` is contraindicated by C-001. At four pool slots, four stuck responses saturated all four and the fifth timed out. Tickets, if adopted, cannot mean pinning a DB connection throughout network transfer.
- **Memory and backpressure:** Whole-response staging requires a strict maximum body size and concurrency budget; high-water behavior, HTTP backpressure and stalled sockets must be bounded. A slow reader cannot hold emergency global disable unboundedly.
- **Latency:** Measure contended and uncontended p50/p95 with N, event timing and scope. Existing C001 had **N=5 saturated connection-acquisition samples** (p50/p95 386/386 ms), five uncontended samples and a separate blocked writer in the synthetic max4 experiment. This is *not* production SLO evidence. D-006 must set thresholds before implementation.
- **Retry/rollback:** On `55P03`/`57014`/`40P01`/`40001` where actually reachable, bounded retries may restart authorization + entire response under fresh scope. Writer rollback cannot be mistaken for revocation; unknown COMMIT cannot be mistaken for rollback. CAS stale writers must have no grant side effect.
- **Two writers:** A separate User emergency-disable and an Organization grant revoke may race. Cross-domain fences must not produce a cycle; emergency cannot wait indefinitely on slow reader or ordinary revoke lock.
- **Multi-Org and multi-Location:** Invalidate by persisted membership/Organization/Location, and by User globally for emergency. Retained B remains available only when B data has no A-derived aggregate or cursor. A user may belong to more than one Organization; one User disable invalidates all its sessions/reads.
- **Cancellation:** Node `finish` indicates server-side transport completion at a specific layer; `close` alone may mean premature loss. An actual gateway or lower network layer needs its own terminal semantics and unforgeable acknowledgement. Partial protected prefix already sent cannot be undone.

## Smallest justified change envelope (conditional only)

**Definitely relevant if a runtime GO later:** the five reader/controller/queries, Staff Management canonical grant revoke, global User-disable executor, Staff session admission, response emission and cancellation, test harness and typed authorization scope. Exact changes depend on approved protocol; there is currently **NO authorization to edit** any of these.

**Conditional on Owner choice:** durable ticket/epoch persistence, egress controller/gateway supervisor, typed transport lifecycle API, coordinating User and Location scope generation, response-size/latency metrics. All would need separate source-of-truth and migration/deployment review.

**Not justified yet:** a new public endpoint, global Nest interceptor across all routes, broad authorizer redesign, new permission role, silent database migration, LB-only "drain" assumption, long-held database sessions, UI changes or a speculative shared cache as the sole authority.

## Decision gate

D-001: Positive ACK + trusted final egress fence, or refuse COMMIT under uncertainty; plain ticket/TTL is rejected.

D-002: Owner must select concrete bounded emergency behavior under a live unacknowledging replica, backed by real infrastructure fencing; contract must remain DEC081 strong.

D-003: Candidate fail-closed temporary handling while infrastructure is absent: deny affected new **read admission**, suspend hazardous endpoints, or explicitly queue/refuse ordinary revoke; none retroactively fixes already active requests and none authorizes weakening DEC081.

D-004: Decide which durable coordination/invalidation store, schema and operational ownership; persistence alone has no egress proof.

D-005: For mixed-location contact reads, choose full authorized-scope recomputation **only if complete equivalence and transport fence verified**; otherwise fail-close whole response before first byte.

D-006: Define bounded maximum pending readers, response bytes, writer latency, emergency deadline, failure recovery and measured pool limits, including process partitions.
