## 3. ما تم تنفيذه في Option 3

### تنظيم الواجهة

- أعلى الصفحة: عنوان **Resource inspector**، ووسم واضح بأن البيانات تجريبية، **وست بطاقات KPI**.
- مفتاح تبديل **Key Slots / Parking Spots** وفلاتر الحالة: All / In use أو Occupied / Available / Inactive.
- قائمة موارد مستقلة يسارًا أو يمينًا حسب اللغة، ولوحة تفاصيل المورد المحدد بالطرف المقابل.
- على الهاتف، تظهر القائمة والتفاصيل بالتتابع بدل تزاحم عمودين، مع زر رجوع، Escape واستعادة التركيز.
- حفظ سياق Location واللغة والمظهر في تفاعل المعاينة فقط، بلا كتابة في Backend.

### إبراز لوحة السيارة

- قائمة المفاتيح والمواقف تعرض لوحة السيارة المرتبطة بخط أوضح بدل إخفائها ضمن تفاصيل صغيرة.
- لوحة التفاصيل تعرض المركبة فوق حالتي Configuration/Usage.
- تُنظَّم اللوحة إلى حروف كبيرة ومسافات موحدة، وتُعزل باتجاه LTR عند العربية.
- الترتيب الصادق: **رقم اللوحة** (مثل `DEMO 4821` في K-02 وP-02) ← **وصف مؤقت** إذا غابت اللوحة (K-03/P-03) ← **Vehicle identity unavailable** إذا كان المورد مشغولًا دون هوية مركبة (K-08/P-08).
- المورد النشط AVAILABLE يعرض **No vehicle assigned**، بينما المورد غير النشط/UNKNOWN يعرض **Vehicle association unknown**، دون اختلاق حالة غياب مؤكدة.
- تم اختيار مثال مشغول مثل K-02 / P-02 مبدئيًا لإظهار اللوحة فور فتح التصميم، من دون إلغاء اختيار المستخدم لاحقًا.

### توحيد الخط والمظهر

- خط مطابق لسلسلة Dashboard المرجعية: `Inter, "Segoe UI", Tahoma, Arial, sans-serif` (مع fallback بحسب الخطوط المثبتة).
- تعديل أحجام النصوص وأوزانها والتباين داخل التصميم الثالث فقط، خصوصًا الأرقام واللوحات والبطاقات والعناوين.
- دعم EN/LTR وAR/RTL، وLight/Dark.
- عرض KPIs بستة أعمدة على الشاشات الكبيرة، وثلاثة على المتوسطة، وعمودين على الهاتف.

### إزالة البحث غير المدعوم

بناءً على تأكيد المالك أن Backend لا يوفر البحث:

- أزيل `<input type="search">` وشريطه وأيقونته واختصار `/`.
- حُذفت حالة `state.search`، والتصفية النصية المحلية، وevent listeners الخاصة بالبحث، ومفاتيح ترجمة البحث، وCSS المرتبط به.
- بقيت فلاتر الحالة وعرض الموارد المختارة، مع عبارة فراغ مناسبة `No resources in this view` / `لا توجد موارد في هذا العرض`.
- لم تتم إضافة endpoint أو تعديل Backend لتعويض الميزة.

### بقية ما احتُفظ به

- معلومات المورد، حالتا Configuration/Usage، منطقة الوقوف لـParking Spots فقط، وسجل عهدة تجريبي للمفاتيح.
- حالات العرض المحلية normal/empty/loading/error.
- معاينات محلية فقط لإنشاء خانة/موقف/منطقة جديدة، دون حفظ.
- ملصق QR توضيحي غير قابل للمسح التشغيلي، مع عرض وطباعة وتنزيل معاينة، وقيود على المورد غير النشط.
- لوحة المفاتيح وتفاعل النوافذ بما يشمل Tab/Escape وإرجاع التركيز.

## 4. الاختبارات والدليل

**المصدر الرئيسي:** `design/issue304/qa/option3-refined-results.json` وتقريره المقروء `design/issue304/evidence/option3-refined-qa.md`.

أبرز النتائج:

- **480/480** قيم KPI صحيحة، **480/480** ظهور/توطين/مقروئية لكل فئة اختبار، وسياق الأرقام المساندة **320/320**.
- **96/96** صحة هوية المركبة في القائمة، و**96/96** في التفاصيل، و**32/32** لإبراز اللوحة في القائمة ومثلها في التفاصيل.
- **16/16** لاختبارات توافق الخط، و**16/16** لعناصر التحكم الداخلية التي لا تخرج أفقيًا.
- معاينة QR والتركيز وEscape واستعادة التركيز وإنشاء Draft اجتازت الاختبارات المستهدفة.
- اختبارا `unsupported-search-ui-absent` واختبارا `unsupported-search-shortcut-removed` كلها **PASS**.
- **50 لقطة Edge فعلية**: 32 حالة أساسية عبر عروض 320/390/768/1440، EN/AR، Light/Dark وLocations A/B؛ 16 لقطة لتفاصيل المركبات، ولقطتان للـQR.
- تم فحص JavaScript باستخدام `node --check`، وصحة بيانات الترجمة، واستقلالية HTML عن أي أصول HTTP خارجية في preflight.
- تم فحص preview URL فعليًا: `HTTP 200`. الملفات المستقلة تعمل دون استدعاء API حي.

### العيب المتبقي المعروف — P1 موروث من Shell

عند **320/390px**، قد يلتف زر Sign out ومجموعة تغيير الموقع خارج ارتفاع Header الثابت **64px**، ويغطي جزءًا من الصفحة. استُدل على السبب في ملفات Dashboard الأصلية `shell.css` و`topbar.tsx`، وثُبت تطابق لقطات Shell الثابتة مع الـCSS المرجعي عن طريق SHA-256 في `evidence/shell-parity.md`.

**هذا العيب لم يُصلَح**: إصلاحه يحتاج إذن مالك مستقل لتعديل الـDashboard Shell المجمد، بدل تغيير CSS الخيار الثالث لتمويه المشكلة. نتائج الخيارات الأربعة القديمة لا تُخلط بنتائج الخيار الثالث الأخيرة، كما أن اختبار Zoom أصلي 200% على المتصفح لم يُثبت بشكل مستقل في المعاينة السابقة.

## 7. ما لم يُنجز بعد وما يحتاج قرار المالك

1. **التحويل إلى React/Next.js الحقيقي** داخل Dashboard بعد اعتماد التصميم؛ لا يكفي وجود HTML وحده.
2. **عقود البيانات:** يجب تحديد مصادر API لعرض أرقام ومركبات Key Slots/Parking Spots، ومعرفة ما إذا كان backend يُرجع جميع الحقول المطلوبة؛ حقول Key Slot label وسجل العهدة المعروض حاليًا قد تحتاج عقدًا منفصلًا. لا يمكن اعتبار بيانات المعاينة دليلًا على جاهزية API.
3. **الحالات التشغيلية الحقيقية:** وصل تغييرات الإشغال والعهدة والأحداث والتزامن بالصلاحيات والـBackend، واختبارها.
4. **QR الإنتاجي:** استبدال SVG الزخرفي برمز صالح وخاضع لشروط صلاحيات النظام.
5. **الإضافة والحفظ:** استبدال نماذج العرض غير المستمرة بتدفقات CRUD المعتمدة واختبار authorization.
6. **Header على الهاتف:** معالجة P1 الموروث بتصريح منفصل لتعديل Shell أو قبول العيب صراحة؛ لا ينبغي وصف كامل تجربة الهاتف بأنها جاهزة للإنتاج قبل ذلك.
7. **نطاق الاختبارات:** نتائج Edge تخص ملف HTML الاصطناعي، وليست اختبارات E2E على Dashboard الموثق أو Backend أو Production، ولا تعني أن غياب Search backend تم التحقق منه برمجيًا؛ أُزيل Search بناءً على متطلب المالك الصريح.

## 8. الخلاصة

**مكتمل كتجربة تصميم متقدمة للخيار الثالث**: لوحة المركبة واضحة وصادقة، الخط متناسق، الست KPIs ديناميكية ضمن البيانات التجريبية، البحث غير المدعوم أزيل من الواجهة والمنطق، وكل الإخفاقات الثمانية المتبقية موروثة من Shell ولا تخص Interior الخيار الثالث. **غير مُنفذ في الإنتاج وغير committed**. الخطوة التالية تتطلب قرار المالك قبل الانتقال إلى تنفيذ React/Backend أو تعديل Shell.
