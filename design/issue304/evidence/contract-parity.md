### Findings communicated to Prime

1. **RESOLVED by Prime — location identity mismatch:** initial `foundation/shell.template:35,38-39` and `foundation/shell-controls.js:30` hardcoded `Meridian Grand Hotel` / `Cedar Plaza`. Prime replaced names with fixture-injected shell variables and locale-aware labels. Static QA's four HTML files confirm matching shell extracts and embedded canonical location records; live locale and switch interactions remain subject to browser QA.
2. **RESOLVED by Prime — missing positive unavailable-identity case:** initial fixture lacked an associated vehicle with neither plate nor descriptor. Prime added `K-08` / `P-08` with `usage:IN_USE` / `usage:OCCUPIED` and `vehicle:{}`. Four concepts must render **Vehicle identity unavailable** / **هوية المركبة غير متاحة** on these records, while preserving all others.
3. **Key label and historical custody are speculative:** fixture's `label` and `custody` arrays are useful for design, but have no parity with a single current Key Slot management read; the actual normalized event enum names differ from fixture display shorthand. Include small disclosure near relevant details.
4. **Existing API boundaries:** status is configuration, usage is distinct; no resource management status-change/delete/update route exists. The final design could propose controls only with explicit future-contract scope, outside current functionality; prototype interactions must not pretend to execute writes.
